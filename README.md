# Markdown2Anything

**写一次，发到所有平台。**

微信公众号 · 知乎 · 博客园 · 小红书 · Twitter · PPT · Word——在 VS Code 中完成排版、截图、AI 文案、平台同步与导出。

---

## 你还在重复这些吗？

写完一篇技术文章，真正的工作才刚开始——

- 微信公众号：粘贴进去，代码块炸了，图片重传，公式消失
- 知乎：同上，再来一遍
- 小红书：截图、裁图、配文案、标签一个个打，传图
- Twitter：重写成英文串推，280 字一条，不知道怎么拆
- PPT：「能不能帮我把这篇文章做成 PPT？」——然后自己做到凌晨

**Markdown2Anything 把这些全变成几次点击。**

---

## 上手只需 3 步

**1. 安装插件**

需要 VS Code 1.100 或更新版本。插件市场搜索 `Markdown2Anything`，或：

```
ext install marsggbo.markdown2anything
```

本地 5.0.0 安装包可通过扩展面板的「从 VSIX 安装…」选择，或在安装包目录运行：

```bash
code --install-extension ./markdown2anything-5.0.0.vsix
```

**2. 打开预览**

打开任意 `.md` 文件 → `Cmd+Shift+W`（Mac）/ `Ctrl+Shift+W`（Windows）

**3. 选平台，点按钮**

右侧面板直接操作。AI 文案功能需先配置一次 LLM：工具栏 `⚙️ LLM` → 选预设（DeepSeek / 硅基流动等）→ 填 API Key → 保存。

## 发布到各平台

### 5.0.0 单平台与多平台同步（VS Code）

打开并保存 Markdown 文件，在预览工具栏的「微信」「知乎」菜单中，首项「同步与配置（官方接口）」进入对应平台工作台；新增「博客园」按钮及同名菜单项。也可以点击「多平台同步」，一次选择多个目标平台。

| 命令面板命令 | 打开范围 |
|-------------|----------|
| `markdown2anything.syncWechat` | 微信公众号官方草稿 |
| `markdown2anything.syncZhihu` | 知乎官方文章发布 |
| `markdown2anything.syncCnblogs` | 博客园草稿、发布或更新 |
| `markdown2anything.syncPublish` | 多平台同步，编排所选平台 |

单平台与多平台复用同一套账号和同步能力。日常只需修改一个文章标题、勾选平台，然后点击「同步」。账号保存后默认折叠，摘要、话题等更多选项按需展开，不再分别填写平台标题，也不需要手动生成和逐项确认平台预览。

1. 首次展开平台的「账号配置」，填写并保存账号；下方「如何获取配置」提供官方链接和操作步骤。凭证存入 VS Code **SecretStorage**，后续复用。
2. 按需点击「测试连接」，不需要填写文章标题、封面或话题，测试不会创建或发布文章。
3. 修改自动提取的文章标题，勾选平台；公众号选择必需封面，博客园默认保存草稿。
4. 点击「同步」，插件自动转换正文并上传图片，再弹出最终确认框，明确各平台是存草稿还是公开发布；确认后提交。取消确认不会创建或发布文章，已上传的图片素材可能保留在平台。

同步后可到公众号、博客园后台核对草稿再自行发布。知乎官方接口仅支持直接公开发布，界面会明确提示。正文预览和历史记录保留在折叠的「同步结果与历史」中，作为可选查看项。

| 平台 | 账号与前提 | 确认后执行与限制 |
|------|------------|----------------|
| 微信公众号 | `appid` / `appsecret`（界面为 AppID / AppSecret）；配置调用机器出口 IP 白名单，并具备素材、草稿接口权限 | 直连微信官方 API，**仅创建草稿**，不群发；必须选择封面，准备阶段上传为永久素材，使用其 `thumb_media_id` |
| 知乎 | AppKey / AppSecret，并在 [知乎官方发布授权页](https://www.zhihu.com/playground/zhihu-publisher) 完成定向授权 | 官方 OpenAPI **仅发布文章**，不支持云端草稿、更新文章或独立封面；支持话题、评论权限、目录及创作声明。用户使用 AI 生成的内容须显式选择 `ai_creation` 声明，插件不会自动选择 |
| 博客园 | 开启 MetaWeblog，提供 `blogName`（博客地址中的名称）、`username` 和访问令牌 `token` | 以 **HTML** 创建草稿或发布；可填 `postId` 更新已有文章，支持分类、标签、评论开关。不支持独立封面，可显式开启 `coverAsFirstImage` 将封面插入正文首图 |

#### 自动填写与更多选项

- **文章标题**：优先使用 front matter 的 `title`，其次为正文标题（优先一级标题，否则首个标题），最后使用不含扩展名的文件名。只编辑一处，所选平台共用；超过平台限制时提示修改，不静默截断。
- **摘要**：依次取 front matter 的 `summary`、`description`、`excerpt`，缺省时提取正文普通段落；去除标记后最多保留 **120 个 Unicode 码点**。默认收进「更多文章选项」，无需手动填写。
- **作者、标签与分类**：读取 `author`（字符串或 `author.name`）、`tags`、`categories`，分别预填公众号作者与博客园标签、分类。
- **本地封面**：从 `cover` / `coverImage` 提取存在的本地文件路径，相对路径以 Markdown 所在目录为基准；远程地址不会自动作为本地封面。

上述信息和发布选项的修改**不会重写 Markdown 原文**。作者、摘要、留言、话题、分类、标签等选项按需展开，已保存的账号和默认偏好可以复用。

#### 不发布文章的连接测试

「测试连接」只测试账号与平台接口，不读取当前文章、不检查标题或封面、不创建发布任务，也不创建、更新或发布文章。测试单个平台时，其他平台的配置不影响结果。

| 平台 | 测试行为 |
|------|--------------------|
| 微信公众号 | 获取账号 token，再读取草稿数量，验证凭证及草稿读取权限；不写入草稿 |
| 博客园 | 调用 MetaWeblog 的 `blogger.getUsersBlogs` 确认账号对应博客；不创建文章 |
| 知乎 | 官方无只读鉴权接口；经提示确认后上传一张插件生成的 320 × 180 测试图，验证实际签名和图片上传链路；不使用当前文章，也不发布测试文章 |

结果直接显示通过、尚未验证或失败；失败时说明原因和排查步骤，例如缺少密钥、IP 白名单、权限或博客名不匹配，详细检查项可展开。取消知乎测试图上传时不会标为通过。连接或媒体上传测试通过不等于文章写入权限已验证，实际提交结果仍以平台响应为准。测试无需 LLM、Python 或 MCP。

话题为可选项。可粘贴 `https://www.zhihu.com/topic/19555547/hot` 这样的完整知乎话题链接，支持 `/hot`、`/newest`、`/top-answers` 及分享参数；多个链接用换行或中英文逗号分隔。不填写时不发送话题字段，不接受话题名称或单独的数字编号。

#### 本地知乎凭证与共享配置

知乎账号优先读取 VS Code SecretStorage；未保存账号且允许本地回退时，读取完整的 `ZHIHU_OPENAPI_APP_KEY` / `ZHIHU_OPENAPI_APP_SECRET` 环境变量对，其次为 `~/.zhihu/openapi-credentials.json`。完整环境变量对与共享文件中的完整凭证不一致时会报告冲突，请统一为同一套账号。没有完整凭证对时，仅在已有 AppKey 的前提下，才可用 `~/.zhihu/.sync_key` 补充 AppSecret。

账号区域的「使用本地知乎账号」（`useLocalZhihu`）可按需将本地凭证导入 SecretStorage。**「清除账号」同时禁用本地自动回退**，不会因环境变量或共享文件仍存在而自动恢复；需要再次显式导入本地账号，或手动保存账号。

源码环境中，统一使用共享配置脚本。先将 AppSecret 单独保存在仅本人可读的本地文件中，再从仓库根目录运行以下命令；`PUBLIC_APP_KEY` 与路径均为占位示例：

```bash
node scripts/configure-zhihu-local.js --app-key PUBLIC_APP_KEY --secret-file /absolute/path/to/zhihu-secret --check
node scripts/configure-zhihu-local.js --app-key PUBLIC_APP_KEY --secret-file /absolute/path/to/zhihu-secret --write
```

`--check` 仅检查本地配置的完整性、一致性与权限，不写文件、不验证在线授权；`--write` 将一致的完整凭证安全写入 `~/.zhihu/openapi-credentials.json`，不会覆盖冲突凭证。共享目录 / 文件权限为 `0700` / `0600`（依操作系统权限语义）。**AppSecret 只通过 `--secret-file` 读取，不要把密钥放进命令参数、文档或仓库。** 实际账号凭证在本机单独配置；本地配置成功仍需完成知乎定向授权，并遵循上述验证边界。

部分平台失败时，「重试失败平台」只处理失败项，成功项不会重发；准备好后再点击「同步」并确认即可。`unknown`（结果未知）可能已经写入平台，必须先到平台后台核对，不参与自动重试，也不会自动重发。

正文、本地图片、封面、主题或发布选项变化后，需要重新同步；最终确认期间内容或账号变化时，插件会停止提交，避免误发旧内容或使用其他账号。

新同步链路除公式 / SVG 转位图需要可用的 Chrome / Edge（Chromium 内核）外，其余处理使用纯 Node.js，无需 Python 或 MCP。插件会自动查找 Playwright 缓存（含 `chrome-linux64`）和系统浏览器；云端无图形界面时，在设置 `markdown2anything.browserPath` 中填写 chrome 可执行文件路径，或设置环境变量 `EXE` / `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`。Linux 会自动附加 `--no-sandbox`。没有 sudo 时，可先运行 `npx playwright@1.59.1 install chromium`（不要加 `--with-deps`）。4.3.1 已用一篇包含 11 张图片和 99 处公式的文章完成真实知乎图片上传与文章发布，提交前核对全文、图序和代码一致；其中表格内 1 处公式按接口限制保留为 LaTeX 文本，其他 98 处使用知乎公式。水印未就绪时使用服务端真实原图。该结果限于本次账号和文章，公众号、博客园仍需各自实际验证。

以下原有复制、浏览器填充与兼容发布入口仍保留，在对应平台菜单中位于官方同步入口之后；它们沿用各自流程。上述单平台 / 多平台命令与工作台目前面向 VS Code，其他端的能力以各端实现为准。

### 📱 小红书——最省事的长图发布流程

1. 工具栏点 `📱 小红书`
2. 选导出模式：**默认 HTML 截图**（保留你的主题风格）或 **手机自适应截图**（1080×1440，适合手机阅读）
3. 点「📸 生成预览」，满意后点「💾 一键导出」
4. AI 自动写好标题 + 正文 + 标签，你来改改
5. 点「🚀 发布小红书」——浏览器自动打开，图传好、字填好，你只需最后点「发布」

两种模式都有完整的尺寸、字号、内边距控制，参数可以「★ 设为默认」记住，随时「↺ 出厂值」还原。

### 🟢 微信公众号

菜单首项「同步与配置（官方接口）」打开公众号工作台，通过官方 API 创建草稿；也可复制带内联样式的 HTML，粘贴到公众号编辑器后核对排版、代码高亮、公式和图片。原有经第三方 FastPen 上传草稿的兼容入口仍保留。

### 🔵 知乎

菜单首项「同步与配置（官方接口）」打开知乎工作台，通过官方 OpenAPI 发布文章。原有浏览器入口可打开知乎编辑器并填入标题、正文、代码和公式；两者授权与能力不同。

### 博客园

工具栏「博客园」按钮 →「同步与配置（官方接口）」打开博客园工作台，复用上述账号、HTML 预览与确认流程，按选项创建草稿、公开发布或更新指定 `postId` 的文章。

准备时会显示账号验证、图片读取和上传进度。图片上传最多等待 120 秒，账号查询最多等待 30 秒。连接错误会说明超时、DNS、证书或连接中断等已知原因；请按提示检查网络、代理或证书，鉴权错误则核对 MetaWeblog 是否开启、用户名及访问令牌。准备失败尚未提交文章，可点击重试准备并复用本任务已成功上传的图片；若文章提交显示「结果待核实」，先到后台核对，避免重复创建。

### 🐦 Twitter (X)

AI 把长文拆成串推 thread，每条控制在 280 字内，配图自动按顺序挂到各条推文上。

## AI 功能

所有 AI 功能共用一套 LLM 配置，接任意 **OpenAI 兼容接口**：

| 预设 | 接口 |
|------|------|
| 硅基流动 | `api.siliconflow.cn/v1` |
| DeepSeek | `api.deepseek.com/v1` |
| OpenRouter | `openrouter.ai/api/v1` |
| Groq | `api.groq.com/openai/v1` |
| 本地 Ollama | `localhost:11434/v1`（无需 Key）|
| OpenAI | `api.openai.com/v1` |

选预设自动填好接口地址和模型名，支持同时保存多套配置，可**重命名、一键切换**（同一平台不同 Key 各起一名互不覆盖，Key 加密存本地）。

**AI 能做什么：**
- 小红书文案：标题 + 正文 + 标签，生成后可手动改
- Twitter 串推：按字数自动拆分，控制语气和风格
- PPT 改写：把文章重写成演讲结构，代码 / 图片 / 公式原样保留
- 每次生成自动存档，`◀ ▶` 切换版本对比，随时回滚

## 安全

- 新工作台手动保存或显式导入的平台账号凭证存入 VS Code SecretStorage，不写入发布任务文件；知乎支持上述本地凭证回退，清除账号后保持禁用回退，直至显式重新导入。原有入口沿用各自的凭证配置方式。
- 本地任务位于扩展的 `globalStorageUri/publishing`，包含未发布正文、准备后的内容、媒体引用与任务状态，**不含账号凭证**。目录 / 文件按 `0700` / `0600` 创建（权限语义取决于操作系统），请按未发布内容管理这些文件。
- 新工作台直连平台 API；连接测试不创建发布任务或文章，知乎测试会在确认后上传生成的测试图。点击「同步」自动准备图片，最终确认后按平台能力创建草稿、发布或更新。
- 原有浏览器自动化入口使用 Playwright 和登录 Cookie，默认 `publish.mode=prepare`，填好内容后由你在网页确认发布；`auto` 模式可自动点击发布。这与新工作台的 prepare / execute 是两套流程。
